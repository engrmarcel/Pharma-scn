## Known limitations and risks

1. MariaDB 10.4 locally versus MySQL 8 in production. CI runs the suite on MySQL 8 on every push.
2. Regulator directory URLs and verification document requirements (only `business_registration` for now) need compliance review.
3. No integration with NAFDAC exists. Verification is manual and evidenced.
4. Seeded plan prices are NULL until the commercial team sets them.
5. During earlier testing, a too-broad cleanup command may have stopped another local project's `php artisan serve` process.
6. Integration gateway (Phase 5):
   - **Tested only against fakes.** SFTP exchange was tested against a fake filesystem, not a live SFTP server, and webhooks against a faked HTTP client.
   - **Field names to confirm.** The SAP IDoc segment and field names follow the standard MATMAS and BATMAS definitions and must be confirmed against each customer's system. The Dynamics 365 and Oracle EBS templates are starting points.
   - **Not built:** SOAP, EDI (X12/EDIFACT) and OData pull adapters. The supported path for these is the customer's middleware pushing to the REST, file or IDoc intake.
   - **Mapped but not applied.** Transactional inbound entities (purchase and sales orders, shipments, receipts, traceability and recall events) can be mapped and validated, but are not applied yet; traceability and recall follow in Phase 7.
   - **No web screens.** There are no screens for integration administration; it works through the API only.
7. CRM (Phase 6):
   - **Rule-based assignment.** Revenue and product-unit targets are attributed through the customer's current territory and representative, so reassigning a customer moves its history with it.
   - **Route order** is straight-line nearest neighbour, not road routing.
   - **Samples** are recorded, not issued from stock.
   - **Web coverage.** The only web screen is the supervisor dashboard; the rest of the CRM works through the API and the app.
   - **The app** covers My day, detailing and feedback. Plans, opportunities and interactions are captured through the API (the sync type for interactions exists; the app has no screen for it yet).
   - **Not verified on a device.** The new app screens were checked by analysis and unit tests, not on a physical device.
